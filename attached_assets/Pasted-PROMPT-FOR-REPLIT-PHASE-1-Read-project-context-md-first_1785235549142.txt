PROMPT FOR REPLIT — PHASE 1

Read project_context.md first so you have full context on the project
before doing anything.

Build the following for the SEO Operating System backend:

1. Mongoose models:
   - User: email (unique), passwordHash, name, createdAt
   - Workspace: name, ownerId (ref User), members: [{ userId, role:
     enum ['owner','admin','member'] }]
   - Site: workspaceId (ref Workspace), domain (string, normalized —
     strip protocol/trailing slash), gscConnected (bool, default
     false), createdAt

2. Auth routes (backend/routes/auth.js):
   - POST /api/auth/register — email, password, name. Hash password
     with bcrypt. Return a JWT.
   - POST /api/auth/login — verify password, return a JWT.
   - Middleware (backend/middleware/auth.js): verifies JWT from
     Authorization: Bearer header, attaches req.user.

3. Workspace routes (backend/routes/workspaces.js), all behind the
   auth middleware:
   - POST /api/workspaces — create a workspace, creator becomes owner
   - GET /api/workspaces — list workspaces the logged-in user belongs to
   - POST /api/workspaces/:id/members — add a member by email (must
     already have an account)

4. Site routes (backend/routes/sites.js), behind auth AND a
   workspace-membership check middleware:
   - POST /api/sites — add a site to a workspace (body: workspaceId,
     domain)
   - GET /api/sites?workspaceId=... — list sites in a workspace
   - GET /api/sites/:id — get one site

5. Frontend:
   - Login and Register pages (simple forms, call the API, store JWT
     in memory/Zustand store — not localStorage, to avoid XSS token
     theft; use an httpOnly-cookie-free in-memory approach with a
     refresh-on-reload strategy, or explain to me if you choose
     differently and why)
   - A "workspaces" page: list workspaces, create new one
   - A "sites" page inside a workspace: list sites, add new site by
     domain

6. Write basic input validation on every route (required fields,
   domain format check) and consistent error responses:
   { success: false, error: "message" }
   and consistent success responses:
   { success: true, data: {...} }

When done, update project_context.md:
- Move Phase 1 into "Current Status" as complete
- Add the new models and routes to their respective sections
- Note the JWT storage approach you chose on the frontend and why
- Set "Next Phase" to Phase 2 — Technical SEO Agent + Audit Pipeline
- Flag anything you had to deviate from in these instructions
